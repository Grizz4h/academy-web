| **Konkret unterstützt** | SIHF Good Practice F3 (DE): Entwicklungsfrage „Wie hast du dich verhalten, um für den/die Puckführer/in eine **Passoption** zu sein?“ — **Passoption** ist etabliert. mobilesport.ch/SIHF-Kontext: **Support** + **Triangle**; Puckführer soll **zwei Anspielmöglichkeiten** haben; Mitspieler **S** gibt **Support**. IIHF/Weiss: **passing option**, **front-side/back-side** — deckt direkte Option und Sicherheits-/Rückseiten-Support ab. **Anschlussoption** als Fachbegriff in den geprüften Quellen **nicht** gefunden; sequenzielle „nächste Verbindung“ ist coaching-logisch (Give-and-go, chain play), aber RinQ-definiert. **Absicherung** im Sinne „Sicherheit hinter der Aktion“ = konzeptionell **back-side support** / defensive Absicherung in DE-Forecheck-Kontext (SIHF: S schließt Raum), nicht 1:1 RinQ-Offensiv-Label. |
| **Primär/Sekundär** | Primär (Passoption, Support); Sekundär (Triangle-Kontext) |
| **Fit zum RinQ-Claim** | **Teilweise** — Passoption + Support gut; Anschlussoption und Absicherung als RinQ-Operationsdefinitionen. |
| **evidence_strength** | **MODERATE** |
| **Sprache anpassen?** | **Optional** — „Anschlussoption“ und „Absicherung“ im Glossar als RinQ-Beobachtungsbegriffe definieren; Passoption darf als Konvention gelten. |

**RinQ-Begriffe ohne Standardbeleg:** `Anschlussoption` (kein etablierter Standardterm in geprüften Quellen); `Absicherung` in RinQ-Offensiv-Relational-Sinn nur teilweise über *Support/back-side* abbildbar.

### A2-C3 — Pass / Carry / Dump / Reset

| Feld | Wert |
|------|------|
| **claim_id** | A2-C3 |
| **Ursprünglicher Claim** | „Welche Aktion wurde ausgeführt: Pass, Carry, Dump, Reset, unklar?“ · „Spieler erzeugen Optionen. Aus Optionen entstehen Entscheidungen.“ |
| **claim_type** | COACHING_CONVENTION + RINQ_MODEL |
| **Quelle(n)** | SRC-08, SRC-01, SRC-10, SRC-11, SRC-09 |
| **Konkret unterstützt** | Karlsson et al.: Taxonomie **Controlled Carry**, **Controlled Pass**, **Dump** (Dump/Chip) für Zonenwechsel — etablierte Analytics-/Coaching-Sprache. IIHF/Rollins: **Pass**, **regroup** (Puck zurück/neu organisieren), **Dump** als offensive Transition-Option. BVHS: **Regroup** = „tactical **reset**“ — Puck zurück zu Supporting Players, Struktur neu. Better Hockey: Chip/D-to-D als **reset**-artige Ausweichoption unter Druck. **Carry** = Puck selbst führen (entspricht Controlled Carry / stickhandling). **Reset** in RinQ (z. B. Rückpass) ist **enger** als BVHS-„Full Neutral-Zone Reset“ / Regroup — teilweise Überlappung, kein einheitlicher IIHF-Glossar-Eintrag „Reset“. Options→Entscheidung: IIHF/Coaching-Konsens, dass Spieler aus verfügbaren Optionen wählen — keine exakte RinQ-Formulierung als Lehrsatz. |
| **Primär/Sekundär** | Primär (Pass/Carry/Dump); Sekundär (Reset/Regroup) |
| **Fit zum RinQ-Claim** | **Teilweise** — Pass/Carry/Dump etabliert; **Reset** eher RinQ-/Coach-Jargon (Regroup-Nähe); vierer-Taxonomie als Ganzes = **RinQ-Beobachtungsschicht**. |
| **evidence_strength** | **MODERATE** |
| **Sprache anpassen?** | **Ja (Glossar empfohlen)** — Dump/Reset im Track kurz definieren oder auf Regroup/Rückpass-Verwandtschaft hinweisen (vgl. A2-MIN-002); Reset nicht als IIHF-Standardterm verkaufen. |

**RinQ-Begriffe ohne Standardbeleg:** `Reset` als eigenständiger Standard-Aktionslabel (Regroup/Reverse/D-to-D näher); die **Vierer-Taxonomie** als geschlossenes Set.
