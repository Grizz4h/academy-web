# RinQ Tank — Curriculum Boundaries

**Status:** verbindliche Content-Rule (Companion zu Content Quality)  
**Gilt für:** Track-Rework, neue Module, Entfernen/Verschieben von Drills, Theorie-Kürzungen, Lernziel-Änderungen

Dieses Dokument fokussiert den **Didaktik-Gate**: Previous → Current → Next.  
Fachliche Claim-Klassifikation und Sprache: `docs/ai-rules/content-quality.md`.  
Vollständiger Rework-Prozess (Capabilities, Phasen, D1–D5): `docs/ai-rules/curriculum-rework.md`.

---

## Kernregel

Tracks nie **isoliert** optimieren.

```text
Previous Track → Current Track → Next Track
```

Ein in sich stimmiger A2, der A3 seinen Startpunkt raubt, ist ein **fehlgeschlagenes** Rework.

---

## Vor jeder Änderung beantworten

### Previous Track

- Was soll der Nutzer **bereits können**, bevor er diesen Track startet?
- Welche Begriffe, Rollen, Beobachtungsschichten sind **Voraussetzung**?
- Wird durch die Änderung eine dieser Voraussetzungen **still entfernt**?

### Current Track

- Welches **eine** neue Capability pro Drill (Complexity Budget)?
- Welche Spielphase gehört diesem Track (Rollen · Struktur · Transition · Zone · System)?
- Was wird **bewusst noch nicht** gelehrt?

### Next Track

- Was erwartet der Folgetrack als **Incoming Skill**?
- Wird dort Inhalt **vorweggenommen** (Phase Boundary verletzt)?
- Entsteht eine **Lücke**, weil Wissen verschoben oder gelöscht wurde ohne Ersatz?

---

## Displacement-Regel

Wird ein Drill entfernt oder vereinfacht:

1. **Capability** identifizieren (nicht nur Drill-Titel).
2. Entscheiden: bleibt · verschiebt · fällt weg · wird neu aufgebaut.
3. Wenn verschoben → **Ziel-Track/Drill** benennen.
4. Wenn weg → bewusst dokumentieren oder Lücke im Abschlussbericht markieren.

Keine Capability still löschen.

---

## Theory ↔ Drill an der Boundary

Wenn an der Grenze zwischen Tracks gearbeitet wird:

- Theorie im Track N darf Begriffe **einführen**, die Track N+1 vertieft — aber nicht die **ganze Phase** von N+1 ersetzen.
- Drill in Track N darf auf Incoming Skills aus N−1 bauen, ohne alles zu wiederholen.
- Reflexion/Feedback darf nicht plötzlich Bewertungskriterien verlangen, die erst in späteren Tracks gelehrt werden.

---

## Abschlussbericht (Pflicht bei Track-Rework)

Im PR / Agent-Abschluss mindestens:

- Boundary Check (Previous / Current / Next) — je eine Zeile
- Incoming / Outgoing Skills
- Capability-Tabelle: blieb · verschoben · neu · unassigned
- Was **nicht** gelehrt wird (absichtlich)
- Content-QA Checkliste A–G aus `content-quality.md` bestätigt
